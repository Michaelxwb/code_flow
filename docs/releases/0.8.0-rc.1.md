# code-flow 0.8.0-rc.1

> 状态: release candidate  
> 日期: 2026-10-22

## 主题

从“记录型门禁”转向“执行型门禁”：required 检查未执行不能 done/verified；执行按 check，证据集中；本地默认 smoke/changed，full 显式或 CI；并行 worktree 证据不冲突。

## 主要能力

- `provisional` 状态与 truthful Done Gate
- manifest v3 `checks + scenarios`，schema2 兼容
- central evidence store（git common dir）、context compaction
- `task verify --layers/--profile/--resume/--deadline/--max-failures/--jobs`
- 环境预检 `env_blocked`、shared/isolated 契约
- 并行 worktree：central evidence、batch smoke、共享环境锁、namespace
- 能力级 plan 与批量 finish
- 生成式 audit 与追溯矩阵
- CI 证据导入（JUnit / Playwright）
- 命令面 16 → 11，旧命令 alias
- `task archive` 运行时归档门禁
- Scenario-First Acceptance：`<需求>.scenarios.md` 唯一场景源（0.9 方向，0.8-rc 已带兼容回退）

## 发布前检查

```bash
python3 -m pytest -q
code-flow sync check --root .
code-flow spec doctor --task-dir <需求目录> --root "$PWD" --json
code-flow audit --task-dir <需求目录> --root "$PWD" --json
code-flow task verify --layers validators,review,e2e --profile full --resume --deadline 1800 --json
```

## 已知限制

- 全量 E2E 建议交给 CI/nightly；本地默认 `changed`，`full` 需显式。
- 0.8 需求没有 scenarios 文件时 audit 输出 `deprecated: true`。
- `input_hash` 仍是整工作树指纹；per-check inputs 哈希是 0.9 目标。
- `accepted_risk` 状态与归档展示仍需产品策略确认。
